# AISG | My Learners — Academic and Whole-Learner Demo

## Faculty and Student academic snapshots (October 2026)

The Faculty class roster can switch its academic result column between **issued report-card outcomes by subject** and, where grade-eligible, **IXL Mathematics diagnostic levels (G1–10)**, **Core Phonics illustrative checks (K–G5)**, and **Fountas & Pinnell text levels (K–G5)**.

Opening a student shows all subjects in an issued report card, with up to three completed school years (2023–24, 2024–25 and 2025–26 when the learner's fictional enrolment history permits), as well as up to three recent assessment snapshots. School-year and programme labels prevent grade scales from being treated as interchangeable. Student demo navigation includes Kindergarten–Grade 2 as well as older learners.

**All named learner profiles and these academic records are synthetic.** The IXL data are simulated *diagnostic levels*, not practice SmartScores or exports. The Core Phonics display is a *fictional 50-item classroom decoding check*, not an official CORE Phonics Survey total or normative score. F&P letters indicate text difficulty, not percentages or overall ability. Current 2026–27 report-card grades are not presented as issued results. This public GitHub Pages demo must never contain identifiable AISG student assessment or survey data.

## Daily-first Faculty and Student experiences (October 2026)

**Faculty:** The selected class roster is now visible directly below the class picker, a search box covering **all classes assigned to the demo teacher**, and a restrained summary of learner count, attendance and available student-experience measures. Report-card subject, IXL, Core Phonics and F&P controls live inside the roster. The class grade distribution is available through a collapsible "Class results breakdown" control rather than blocking daily access. Results across classes are explicitly labelled with the student’s class, relevant subject, previous grade and last issued school year. Each fictional teacher's last selected class and academic mode are remembered locally on that browser. **Classroom guidance deliberately remains at the end of the Faculty learner profile**, after academic and wellbeing data.

**Student:** The first screen now highlights one fictional issued-report result, a recent suitable learning check-in, and a short student-owned reflection, with age-adjusted language for PK–G2, G3–5 and G6–12. Complete report cards and wellbeing check-ins are independently expandable, so older results remain accessible without crowding the landing screen. Inapplicable MAP, IXL, Core Phonics, F&P and pre-Grade-3 wellbeing measures are hidden. Report dates and grade/programme context remain explicit; historical grades are not presented as current-year grades. Reflection drafts are kept only in the user's browser session and are not submitted to a server.

These are interface demonstrations using **entirely fictional** student records. They do not import real grades, attainment, attendance or wellbeing data, and the role selector is not production-level authorisation. Do not use the public GitHub Pages site for genuine student records.


## Leadership overview (October 2026)

The Leaders role now uses the same accessible Noto Sans and calm navy/blue presentation as the Faculty, Student and Board experiences. Its first screen shows only four indicators: fictional learner count (PK3–G12), the share of learners meeting **illustrative** MAP Mathematics and Reading growth projections (only comparable G3–10 tests), and coverage of previously **issued** report cards. These MAP figures are **not** official NWEA norms, and this view does not import or blend the genuine aggregated results available in the Board role.

Student experience presents Engagement and Belonging as concise index cards with response counts and comparisons to the previous check-in. Elementary (G3–5) and Secondary (G6–12) results remain separate when both are present because their questions differ; PK–G2 has no simulated check-in scores.

Two **closed-by-default** sections provide extra depth when needed. *Explore academic measures* shows grade-eligible availability of IXL diagnostic levels (G1–10), fictional Core Phonics decoding checks (K–G5) and F&P reading text levels (K–G5). When a **single grade** is selected, it adds the median **Fall 2026 fictional** check-in value and a distribution of the last issued Mathematics and Literacy report outcomes, grouped only within one issued grade/year/programme scale. It never averages incompatible grading frameworks. *Explore student experience patterns* shows group response counts and the three historical check-in windows. Both sections remain expanded when the leader changes filters.

**These are fictional learning examples, not schoolwide attainment claims.** The public GitHub Pages site has no live student connection, authentication, or approved access controls for individual student data.

## Student Support Services (SSS) — **fictional prototype** (October 2026)

The **SSS** tab is a grade-first, read-only demonstration of a **future access-controlled department workspace**. It uses the **same synthetic students and deterministic learner IDs** as Faculty, Student and Leaders. No real WIDA scores, actual SSS enrolment lists, diagnoses, confidential notes or student support plans are included.

**Quick team view**
- Compact summary for fictional programme membership, language support, learning support and available Elementary WIDA examples.
- Grade selector (PK3–G12), optional learner-name search, and cohorts listed by grade with students sorted **alphabetically by family name, then given name**.
- Collapsible grade lists show the student's class, illustrated EAL/SS/IEP classroom flags, support stream, last-issued Mathematics result, Elementary WIDA snapshot (where appropriate), and **fictional** upcoming review date. The **SSS programme cohort is a separate seeded demonstration membership indicator**: an EAL classroom tag alone does not automatically constitute admission, and Medical/Behavioural tags alone never cause programme membership.
- Faculty class rosters and Faculty learner profiles identify fictional SSS cohort members with a small **SSS** marker; all classroom guidance remains at the **end** of Faculty profiles.

**Selected learner**
- An illustrative, strengths-and-access-oriented team focus, with example review dates and demo language context.
- The **same** attendance, last-issued subject outcomes, MAP Mathematics/Reading observed RIT change (G3–10), IXL diagnostic level (G1–10), mock Core Phonics 50-item decoding result (K–G5), F&P text level (K–G5), and Grade 3+ check-in indices already available through Faculty/Student. These are all **synthetic**; assessment scales are kept separate.
- Example WIDA Screener for **Kindergarten** displays an oral two-domain illustration (Listening and Speaking with an Oral Language composite); **Grades 1–5** display four-domain **WIDA Screener Paper** illustrations (Listening, Reading, Speaking, Writing and an Overall composite). All visible levels are marked **fictional** and confined to 1.0–6.0. The composites are **illustrative placeholders** and **are not calculated from the displayed proficiency levels**; do not use them as reportable WIDA scores. WIDA Screener is an **initial identification** input, not a progress-monitoring series, diagnostic label, placement threshold or substitute for trained staff review.
- Shared classroom strategies from the existing fictional support tags; a collapsed, full academic report-card/history view. No note writing, confidential plans, referrals, counselling records, CPOMS incidents or medical case histories.

**Future access requirements:** GitHub Pages and this role switcher are **not an authentication or authorisation boundary**. Before connecting real school records, AISG must approve a private deployment with staff Microsoft SSO, **server-enforced assignment-based and student-level access**, role-limited flags and source links, revocation, audit logs, data retention rules and safeguarding/health separation. Never place actual student profiles, SSS membership lists, IEPs or WIDA exports into this public GitHub repository or browser-side JavaScript bundle. Only authorised faculty and SSS staff should see the particular support information required for their role.

**Design references:** WIDA's [Screener guide](https://wida.wisc.edu/assess/screener) and [Interpretive Guide](https://wida.wisc.edu/resources/wida-screener-interpretive-guide-score-reports); the coordinated learner views and intervention-progress design principles described by [Panorama Student Success](https://www.panoramaed.com/products/student-success) and [Branching Minds](https://www.branchingminds.com/explore-branching-minds-platform). This demonstration does not copy their software or store intervention/casework.


## Original demo introduction

**[Open the My Learners demonstration](https://edtechevans.github.io/mylearners/)**

A simple, teacher-facing view of **classes, student profiles and the essential information educators look up regularly**. The first release deliberately focuses on finding information rather than launching another workflow or set of daily alerts.

## Four clear sections

| Section | First-release purpose |
| --- | --- |
| **Home** | See assigned teaching groups, learner counts and quick links to the right class |
| **My Classes** | Open a class roster; find students, attendance, recent published academic outcomes, MAP Mathematics growth and classroom guidance |
| **My Learners** | Search across assigned demo groups and open student profiles with illustrated portraits and demographics |
| **MAP Growth** | Compare observed growth to illustrative projected growth by teaching group and student, with RIT history available on individual profiles |

### Student profile
Each fictional learner has an overview, recent academic learning, MAP growth (where assessed), attendance and punctuality, and essential classroom guidance. The design remains growth-first: a change in a valid MAP score is surfaced ahead of the latest RIT value.

### Fictional learner support indicators

The first release displays five clearly labelled, easy-to-recognise **demonstration support tags** on class rosters, in My Learners search results and on individual learner profiles:

- **EAL** — English as an Additional Language
- **SS** — Student Support
- **IEP** — Individualised Education Plan
- **Medical** — essential classroom health/safety guidance indicator
- **Behavioural** — proactive positive behaviour support indicator, not a judgement about the learner

Teachers may select a badge to open the corresponding section of **Classroom guidance** and can filter a roster by any one of the five categories. Multiple badges can appear on one fictional learner. The demonstration is deliberately **enriched with examples**: every fictional class contains examples of all five badges. This must not be interpreted as realistic prevalence.

**Sensitive data and scope:** This is an entirely synthetic feature with no imported student records or actual teacher support assignments. Medical, IEP, SS and Behavioural flags could reveal sensitive learner information in a real school. In production, both the presence of a tag and its underlying details must be role-limited and displayed only to authorised adults with an educational need to know. Approved plans should be accessed through the relevant governed source system, not copied into public HTML, spreadsheets, browser storage, GitHub Pages or an unapproved AI service. The Medical and Behavioural demo cards intentionally contain **no diagnoses, treatment history, incident records or personal case notes**. Do not treat a tag as a fixed description of a learner.

### Deliberately not included in the first release
- Daily **Learning Pulse** alerts, automatic evidence signals and prescribed next teaching steps.
- **My Actions** queues, intervention forms, follow-up documentation and browser-saved action records.
- Suggested **flexible grouping**, predictive insights and student-voice summaries.

Advanced exploratory modules remain in the source repository for possible later development, but **the public launch entry point does not load or expose their interaction workflows**. No first-release feature needs teachers to maintain another to-do list.

## Demonstration data and privacy

- **15 grades:** PK3, PK4, Kindergarten and Grades 1–12.
- **4 classes in every grade, 20 fictional students per class**: 60 classes and 1,200 demo student profiles.
- **115 real AISG faculty names** sourced from the already-public **My Observations 2026–27 working PLC roster**; all faculty-to-class, teacher-to-learner and timetable relationships in the demo are fabricated.
- Fictional student names, illustrations, academic assessments, attendance, MAP achievement and growth, demographic fields and classroom guidance.
- Simulated MAP Growth information only where appropriately assessed in the demo (Grades 3–10). Student profile can show RIT as secondary detail, not the headline.
- Data is fixed at a clearly marked **8 October 2026 demonstration date**; it is not current school information.
- The demo has **no live connection** to PowerSchool, ManageBac, NWEA, medical, counselling, student support, safeguarding or HR systems.
- The public GitHub Pages demonstration **must never use identifiable real student data or actual sensitive staff observation records**.

## Develop and test locally

```bash
python3 -m http.server 8765
# In another terminal:
node --test tests/*.test.mjs
MYLEARNERS_URL=http://127.0.0.1:8765 python tests/e2e/teacher_journeys.py
```

The real-browser test suite requires Playwright and Chromium. It models ten **simulated** teacher journeys and checks all public first-release views across desktop, tablet and phone widths. Simulations cannot replace observation of actual AISG educators using the app.

### Architecture
- `index.html` loads **`src/my-learners-launch.mjs`**, the streamlined public entry point.
- `src/first-release-pages.mjs`: Home and class roster with support filters and badges.
- `src/learner-tags.mjs` and `src/learner-tags-ui.mjs`: synthetic support categories and interactive safe guidance; no live student-support data.
- `src/my-learners-launch.css`: first-release visual refinements, above the AISG shared UI layer.
- `src/v2-pages.mjs`: reusable learner profiles, class lists and MAP Growth screens. Advanced experimental renderers are retained in this historical module only.
- `src/data.mjs`, `src/staff.mjs`, `src/faculty-demo.mjs`: deterministic synthetic data and real-named, fictionally assigned faculty views.
- `src/map-growth.mjs`, `src/map-growth-ui.mjs`: observed growth, projections, and underlying score history.
- `src/integration-contracts.mjs`: disabled integration specifications for a future secure platform.
- `docs/production-readiness.md`: requirements for any genuine student data integration.
- `docs/ux/real-teacher-study-protocol.md`: protocol to evaluate task speed and ease with ten actual AISG teachers.

## Roadmap — only if it proves useful

The first goal is to establish whether teachers can quickly **find the right learner, view meaningful academic evidence, interpret MAP growth and check essential support guidance**. If this helps faculty without increasing administrative workload, additional features can be reconsidered with teacher input.

Operational deployment would require institution-approved secure hosting, staff SSO, server-enforced class/student access, official source integrations, audit logs and privacy/legal approval. None of those are provided by the public demo.
